How to use this guide

All commands run in Ubuntu (WSL), from the lab folder, while the lab is deployed. Define the container prefix once per terminal:

cd ~/projects/mini-dc-lab
P=clab-mini-dc

Each table lists the command and what it proves. Commands marked BLOCKED / DENIED are expected to fail — they demonstrate a security control.

Right after a deploy, wait about 30 s for OSPF / spanning tree, and 2–4 min for TrueNAS (storage01) to boot before testing the SAN (section 9). Check the TrueNAS console at http://localhost:6080/vnc_lite.html?scale=true if unsure.

9. SAN – TrueNAS SCALE iSCSI storage

storage01 runs TrueNAS SCALE 25.10 as a KVM virtual machine. It serves a ZFS mirror pool tank with one zvol per server, published as iSCSI targets restricted by initiator address.

CommandWhat it shows
docker exec $P-storage01 pgrep -a qemu-systemthe TrueNAS VM is running under KVM (accel=kvm)
docker exec $P-db01 ping -c2 10.10.30.10db01 reaches TrueNAS on its dedicated storage NIC
docker exec $P-db01 iscsi-ls -s iscsi://10.10.30.10db01 discovers only its own target storage01.db, LUN 1
docker exec $P-db01 iscsi-readcapacity16 iscsi://10.10.30.10/iqn.2026-09.lab.dc:storage01.db/1reads its 10 GiB LUN (last LBA 20971519 × 512 B)
docker exec $P-backup01 iscsi-readcapacity16 iscsi://10.10.30.10/iqn.2026-09.lab.dc:storage01.backup/1backup01 reads its 4 GiB LUN (last LBA 8388607)
docker exec $P-db01 iscsi-readcapacity16 iscsi://10.10.30.10/iqn.2026-09.lab.dc:storage01.backup/1 || echo DENIEDanother server's LUN is DENIED ("Target not found")

In the TrueNAS web interface

Open https://localhost:8443 (user truenas_admin, accept the self-signed certificate):

WhereWhat it shows
Storage → pool tankZFS mirror of the two data disks, status ONLINE
Datasets → tank/db, tank/backupthe two zvols (10 GiB and 4 GiB) backing the LUNs
Shares → Block (iSCSI) → Targetsstorage01.db allowed from 10.10.30.30/32, storage01.backup from 10.10.30.40/32
Shares → iSCSI → Portalsportal on 10.10.30.10:3260 (SAN only)
Networkenp0s5 = 10.10.30.10/24 (SAN, no gateway), enp0s6 = DHCP (management)

From the VM console (option 8) Open Linux Shell): zpool status tank and zfs list -t volume. To re-apply the configuration at any time: python3 scripts/truenas-setup.py (idempotent).

11. Failover demonstrations

CommandWhat it shows
./scripts/tests.shall 20 automated checks (expected: 20 passed, 0 failed)
./scripts/tests.sh failoverISP + VRRP failover with measured packet loss (cuts links for a few seconds, then restores them)

Live version for a presentation — use two terminals:

# Terminal 1: continuous ping to the Internet
docker exec clab-mini-dc-web01 ping 8.8.8.8

# Terminal 2: cut ISP A, watch the pings continue through ISP B, then restore
docker exec clab-mini-dc-edge-r1 ip link set eth1 down
docker exec clab-mini-dc-edge-r1 ip link set eth1 up

Measured results: ISP failover ≈ 0.2 s (1 lost ping) · core gateway failover (VRRP) ≈ 2.8 s.
